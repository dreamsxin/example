## GSI 修改流程

以下是基于 Google 官方 GSI 镜像进行增量修改的完整流程，无需完整编译 AOSP。

### 1. 获取 GSI 镜像

从 Google CI 下载对应架构的 GSI：

```bash
# 访问 https://ci.android.com/builds/branches/aosp-android14-gsi/grid
# 选择 aosp_arm64-userdebug（真机）或 aosp_x86_64-userdebug（模拟器）
# 下载 *-img-*.zip，解压得到 system.img
```

或者用 `lunch` 目标直接编译一个最小 GSI（如果你有 AOSP 源码树）：

```bash
lunch aosp_arm64-userdebug
make systemimage -j$(nproc)
# 产物在 out/target/product/generic_arm64/system.img
```

### 2. 解包 system.img

GSI 通常是 sparse 格式，需要先转换：

```bash
# sparse → raw
simg2img system.img system_raw.img

# 查看分区信息
file system_raw.img
# 应该显示 ext4 filesystem

# 创建挂载点并挂载
mkdir /mnt/system
mount -o loop,rw system_raw.img /mnt/system
```

如果镜像空间不够放入额外文件，先扩容：

```bash
# 扩容 512MB
e2fsimg system_raw.img 512M   # 或用 resize2fs
truncate -s +512M system_raw.img
e2fsck -f system_raw.img
resize2fs system_raw.img
mount -o loop,rw system_raw.img /mnt/system
```

### 3. 修改系统文件

#### 3.1 注入 Root（su 二进制）

```bash
# 从已编译的 AOSP 或第三方获取 su
# 放置到 xbin 目录
cp su_arm64 /mnt/system/system/xbin/su
chmod 4755 /mnt/system/system/xbin/su
chown root:root /mnt/system/system/xbin/su
```

#### 3.2 修改系统属性

```bash
# 编辑 build.prop
vi /mnt/system/system/build.prop

# 修改/添加以下属性：
# ro.debuggable=1
# ro.secure=0              # 注意：会被部分应用检测
# ro.adb.secure=0          # adb 默认无需授权
# persist.sys.usb.config=adb
```

更隐蔽的做法——只改 `adbd` 行为，不动 `ro.secure`：

```bash
# 替换 adbd 二进制（需要自行从源码编译修改版）
cp adbd_patched /mnt/system/system/bin/adbd
chmod 755 /mnt/system/system/bin/adbd
```

#### 3.3 安装系统级 CA 证书

```bash
# 将你的抓包证书（如 mitmproxy/Burp）转为 Android 系统证书格式
CERT_HASH=$(openssl x509 -inform PEM -subject_hash_old -in burp_ca.pem | head -1)
cp burp_ca.pem /mnt/system/system/etc/security/cacerts/${CERT_HASH}.0
chmod 644 /mnt/system/system/etc/security/cacerts/${CERT_HASH}.0
```

#### 3.4 修改默认网络安全配置

```bash
# 创建全局 network_security_config.xml
mkdir -p /mnt/system/system/etc/xml

cat > /mnt/system/system/etc/xml/network_security_config.xml << 'EOF'
<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
    <base-config cleartextTrafficPermitted="true">
        <trust-anchors>
            <certificates src="system" />
            <certificates src="user" />
        </trust-anchors>
    </base-config>
</network-security-config>
EOF
```

> 注意：此配置仅对未自定义 `networkSecurityConfig` 的应用生效。对于自定义了该配置的应用，仍需通过 Frida hook 或重打包绕过。

#### 3.5 预装工具

```bash
# Frida Server
cp frida-server-16.x.x-android-arm64 /mnt/system/system/bin/frida-server
chmod 755 /mnt/system/system/bin/frida-server

# tcpdump
cp tcpdump_arm64 /mnt/system/system/xbin/tcpdump
chmod 755 /mnt/system/system/xbin/tcpdump

# 可选：添加开机自启脚本
cat > /mnt/system/system/etc/init/frida-server.rc << 'EOF'
service frida-server /system/bin/frida-server -l 0.0.0.0
    class late_start
    user root
    seclabel u:r:magisk:s0
    disabled

on property:sys.boot_completed=1
    start frida-server
EOF
```

#### 3.6 处理 SELinux

最简单的方式是设为 permissive（牺牲安全性换取兼容性）：

```bash
# 方法1：修改内核命令行（需要同时修改 boot.img）
# androidboot.selinux=permissive

# 方法2：在 GSI 中设置属性
echo "ro.boot.selinux=permissive" >> /mnt/system/system/build.prop
```

如果要保持 enforcing 并添加自定义策略：

```bash
# 需要 sepolicy-inject 工具
# 从 https://github.com/nicene-nern/sepolicy-inject 获取
sepolicy-inject -s su -t su -c process -p transition -P /mnt/system/system/etc/selinux/plat_sepolicy.cil
# 实际操作中，CIL 格式的策略修改比较复杂，permissive 是更务实的选择
```

### 4. 重新打包

```bash
# 卸载
umount /mnt/system

# raw → sparse（减小体积）
img2simg system_raw.img system_modified.img

# 验证
simg_dump system_modified.img
```

### 5. 刷入设备

```bash
# 解锁 Bootloader（一次性操作）
adb reboot bootloader
fastboot flashing unlock

# 刷入 GSI（需要设备支持 Project Treble）
fastboot flash system system_modified.img

# 如果是 A/B 分区设备
fastboot flash system_a system_modified.img
fastboot flash system_b system_modified.img

# 清除数据并重启
fastboot -w
fastboot reboot
```

对于模拟器，直接指定镜像启动：

```bash
emulator -system system_modified.img -writable-system
```

### 6. 启动后验证

```bash
# 验证 root
adb shell id                    # 应显示 uid=0(root)
adb shell su -c whoami          # root

# 验证证书
adb shell ls /system/etc/security/cacerts/ | grep $(CERT_HASH)

# 验证 frida
adb shell frida-server --version
adb shell ps -A | grep frida

# 验证抓包
adb shell tcpdump -i any -c 5
```

### ⚠️ 关键注意事项

- **AVB (Android Verified Boot)**：Android 8+ 设备启用了 AVB，修改 system 分区后需要禁用校验，否则无法启动。刷入时加 `fastboot flash --disable-verity --disable-verification vbmeta vbmeta.img`
- **动态分区**：Android 10+ 使用 `super` 分区包含 `system/vendor/product`，需要用 `lpunpack` / `lpmake` 处理，流程更复杂
- **GSI 兼容性**：GSI 只替换 system 分区，依赖设备 vendor 分区的 HAL 实现，部分硬件功能（如相机）可能异常

如果目标只是模拟器环境下的逆向分析，跳过 AVB 和动态分区的问题，直接用 `emulator -writable-system` 是最省事的路径。
