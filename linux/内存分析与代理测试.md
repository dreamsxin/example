# 运维排查参考：内存分析与代理测试

---

## 第一部分：Linux 进程内存分析命令汇总

### 1. 快速总览

```bash
# 查看进程整体内存（RSS、VSZ、内存占比等）
ps -o pid,ppid,user,vsz,rss,pmem,pcpu,etime,cmd -p <PID>

# 按内存排序显示所有进程
ps aux --sort=-rss | head -20

# 实时查看进程内存变化
watch -n 2 'ps -o rss= -p <PID> | awk "{printf \"RSS: %.2f MB\n\", \$1/1024}"'
```

### 2. 精确内存分析（PSS/USS）

```bash
# 使用 smem 查看精确内存（需安装 smem）
sudo smem -P <进程名> -c "pid user command rss pss uss"

# 查看进程内存映射汇总（内核提供的精确数据）
cat /proc/<PID>/smaps_rollup

# 查看内存映射详情并按 RSS 排序
pmap -x <PID> | sort -k3 -n -r | head -30
```

**smaps_rollup 关键字段解读**：
- `Rss`：实际物理内存
- `Pss`：按比例分摊共享内存后的真实占用
- `Pss_Anon`：匿名内存（堆、栈、运行时）
- `Pss_File`：文件映射内存（二进制、库代码段）
- `Private_Dirty`：进程独占的脏页
- `AnonHugePages`：透明大页使用量

### 3. Go 程序专用内存分析

```bash
# 查看 Go 运行时环境变量
cat /proc/<PID>/environ | tr '\0' '\n' | grep -iE 'GOGC|GOMEMLIMIT|GOMAXPROCS'

# 查看线程数（Go 的 M 数量）
ls /proc/<PID>/task | wc -l

# 如果应用暴露了 pprof
go tool pprof -top http://127.0.0.1:<pprof端口>/debug/pprof/heap
go tool pprof -top http://127.0.0.1:<pprof端口>/debug/pprof/goroutine
curl -s http://127.0.0.1:<pprof端口>/debug/pprof/heap?debug=1 | head -20
```

### 4. 按连接/文件描述符维度分析

```bash
# 查看进程 socket 数量
ls -l /proc/<PID>/fd | grep -c socket
ss -tanp | grep -c 'pid=<PID>'

# 查看文件描述符总数
ls /proc/<PID>/fd | wc -l

# 查看该进程的连接状态分布
ss -tanp | grep 'pid=<PID>' | awk '{print $1}' | sort | uniq -c | sort -rn
```

### 5. 持续监控与泄漏检测

```bash
# 每 2 秒记录一次 RSS
for i in $(seq 1 30); do
  rss=$(awk '/VmRSS/{print $2}' /proc/<PID>/status)
  echo "$(date +%T) RSS=${rss}KB"
  sleep 2
done

# 每 5 秒采样一次，观察趋势
while true; do
  awk '/VmRSS/{print strftime("%T"), $2"KB"}' /proc/<PID>/status
  sleep 5
done
```

### 6. 全局内存与连接统计

```bash
# 查看系统 socket 汇总
ss -s

# 查看内核 socket 统计
cat /proc/net/sockstat

# 按网络命名空间查看（容器场景）
cat /proc/<PID>/net/sockstat
```

### 7. 结合 Go 日志指标解读

日志示例：
```
goroutines=695 heapAllocMB=7 heapSysMB=21 heapReleasedMB=7
stackSysMB=6 rssMB=39 sysMB=34 numGC=20
```

对照关系：
- `rssMB` ≈ `heapSysMB + stackSysMB + runtime 开销`
- `heapAllocMB`：活跃堆对象，很小说明无泄漏
- `stackSysMB`：goroutine 栈总量，`goroutines × 平均栈大小`
- `numGC`：GC 次数，短时间激增需关注

## 第二部分：代理连接问题测试（脱敏版）

### 1. 问题描述

使用 curl 通过 SOCKS5 代理访问外网失败：

```bash
curl -v -x socks5://<用户名>:<密码>@<代理地址>:<端口> https://example.com
*   Trying <代理地址>:<端口>...
* Connected to <代理地址> (<代理地址>) port <端口> (#0)
* connection to proxy closed
* Closing connection 0
curl: (97) connection to proxy closed
```

**现象**：TCP 层能连上代理端口，但 SOCKS5 协议握手阶段代理主动关闭连接。

### 2. 测试环境（脱敏）

| 项目 | 内容 |
|---|---|
| 客户端 | Linux |
| 代理地址1 | `localhost:<端口>` |
| 代理地址2 | `<代理IP-1>:<端口>` |
| 代理地址3 | `<代理IP-2>:<端口>` |
| 代理凭据 | 用户名 `<用户名>`，密码 `<密码>` |
| 目标 URL | `https://example.com` |
| 测试工具 | `curl`、`nc`、`od` |

### 3. 测试步骤与结果

#### 3.1 本地代理 `localhost:<端口>`

```bash
curl -v -x socks5://<用户名>:<密码>@localhost:<端口> https://example.com
```

**结果**：TCP 连接成功，代理立即关闭连接，curl 报错 `(97)`。
**分析**：代理端口可能不是 SOCKS5 服务，或代理进程异常。

#### 3.2 远程代理 `<代理IP-1>:<端口>`

```bash
printf '\x05\x01\x00' | timeout 5 nc -w 3 <代理IP-1> <端口> | od -A x -t x1z
```

**输出**：
```
000000
```

**结果**：TCP 连接成功，但无任何响应数据。
**分析**：非 SOCKS5 服务 / IP 白名单限制 / 代理故障。

#### 3.3 远程代理 `<代理IP-2>:<端口>`

```bash
printf '\x05\x01\x00' | timeout 5 nc -w 3 <代理IP-2> <端口> | od -A x -t x1z
```

**输出**：
```
000000 05 ff
000002
```

**结果**：代理返回 `05 ff`。
**分析**：是 SOCKS5 服务，但不接受“无认证”，要求客户端提供认证。

### 4. SOCKS5 协议关键说明

#### 4.1 客户端握手包格式（`\x05\x01\x00`）

| 字节 | 值 | 含义 |
|---|---|---|
| `\x05` | 5 | SOCKS 版本：SOCKS5 |
| `\x01` | 1 | 支持的认证方法数量 |
| `\x00` | 0 | 方法编号：无认证 |

#### 4.2 代理响应

| 响应 | 含义 |
|---|---|
| `05 00` | 选择无认证，握手成功 |
| `05 02` | 选择用户名密码认证，需继续发送认证包 |
| `05 ff` | 无可接受的方法，拒绝连接 |

#### 4.3 用户名密码认证流程

先发：
```bash
printf '\x05\x01\x02'
```
若代理回 `05 02`，再发 RFC 1929 认证包：
```bash
printf '\x05\x01\x02\x01\x0c<用户名>\x0c<密码>' | timeout 5 nc -w 3 <代理IP-2> <端口> | od -A x -t x1z
```
期望返回：
```
000000 01 00   # 认证成功
000000 01 01   # 认证失败
```

### 5. 结论

| 代理地址 | 测试结果 | 结论 |
|---|---|---|
| `localhost:<端口>` | TCP 连接后立即关闭 | 非 SOCKS5 服务或代理异常 |
| `<代理IP-1>:<端口>` | TCP 连接成功，无响应 | 非 SOCKS5 / IP 白名单 / 代理故障 |
| `<代理IP-2>:<端口>` | 返回 `05 ff` | 是 SOCKS5，但要求认证 |

**核心问题**：
1. 原 curl 使用的 `localhost:<端口>` 并非有效的 SOCKS5 代理。
2. 可用的 SOCKS5 代理 `<代理IP-2>:<端口>` 需要用户名密码认证，需完成认证流程。
3. `<代理IP-1>:<端口>` 节点无响应，需确认可用性或白名单。

### 6. 后续建议

```bash
# 验证认证流程
printf '\x05\x01\x02' | timeout 5 nc -w 3 <代理IP-2> <端口> | od -A x -t x1z
printf '\x05\x01\x02\x01\x0c<用户名>\x0c<密码>' | timeout 5 nc -w 3 <代理IP-2> <端口> | od -A x -t x1z

# 使用 curl 完整测试
curl -v --socks5-hostname <用户名>:<密码>@<代理IP-2>:<端口> https://example.com

# 排查端口监听
ss -tlnp | grep <端口>

# 抓包分析
sudo tcpdump -i any -A -s 0 'host <代理IP-2> and port <端口>' -w /tmp/socks.pcap
sudo tcpdump -r /tmp/socks.pcap -A -X
```

### 7. 附录：常用命令速查

| 目的 | 命令 |
|---|---|
| 无认证握手 | `printf '\x05\x01\x00' \| nc -w 3 <IP> <PORT> \| od -A x -t x1z` |

| curl HTTP 代理 | `curl -v -x http://<用户>:<密码>@<IP>:<PORT> https://example.com` |
| 查看端口监听 | `ss -tlnp \| grep <PORT>` |
| 抓包分析 | `sudo tcpdump -i any -A 'host <IP> and port <PORT>'` |
