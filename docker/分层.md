# Docker 分层 = 只读镜像层 + 容器可写层，OverlayFS 联合挂载

1. **Docker 镜像层是只读、不可变的**，容器启动时在最上面加一个可写层。  
2. **OverlayFS 负责把只读层和可写层“合并”成一个完整文件系统**，但运行中的容器不能动态替换 lowerdir 层；独立更新通常靠“重新构建镜像 + 重建容器”或“挂载 volume”。

---

## 1. 四层映射到 Docker

| 你的逻辑层 | Docker 中对应 | 说明 |
|---|---|---|
| Base Image | `FROM ubuntu:22.04` 等基础镜像 | OS、libc、证书、包管理器 |
| Toolkit | `FROM base` 后安装工具链 | Python/Node/GCC/Git 等，只读层 |
| Workspace | `COPY` 进镜像，或 volume/bind mount | 代码、任务数据；建议用 volume |
| Writable Layer | 容器最上层 `upperdir` | Agent 运行时写、改、删都落这里 |

Dockerfile 示例：

```dockerfile
# 1. Base Image
FROM ubuntu:22.04 AS base
ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates curl git \
 && rm -rf /var/lib/apt/lists/*

# 2. Toolkit
FROM base AS toolkit
RUN apt-get update && apt-get install -y --no-install-recommends \
    python3 python3-pip nodejs npm build-essential \
 && rm -rf /var/lib/apt/lists/*
ENV PATH="/opt/venv/bin:$PATH"

# 3. Workspace 初始内容
FROM toolkit AS workspace
WORKDIR /workspace
COPY . /workspace
RUN useradd -m agent && chown -R agent:agent /workspace
USER agent
CMD ["/bin/bash"]
```

构建时可以按 target 分开构建：

```bash
docker build --target base -t agent-base .
docker build --target toolkit -t agent-toolkit .
docker build --target workspace -t agent-workspace .
```

实际运行时，更推荐把 Workspace 做成挂载卷：

```bash
docker run -it --rm \
  -v "$PWD/workspace:/workspace" \
  agent-workspace
```

这样代码和任务数据的变化不会写进镜像，也不会只留在容器可写层。

## 2. OverlayFS 如何组合

Docker 的 `overlay2` 存储驱动大致这样组织：

```text
lowerdir：只读镜像层
upperdir：容器可写层
workdir：OverlayFS 工作目录
merged：容器看到的根文件系统
```

手动模拟类似：

```bash
mount -t overlay overlay \
  -o lowerdir=/layers/workspace:/layers/toolkit:/layers/base,upperdir=/layers/upper,workdir=/layers/work \
  /merged
```

规则：

- 读文件：从上层往下找，第一个找到的生效。
- 写文件：如果文件在只读层，先复制到可写层，再修改，即 Copy-on-Write。
- 删文件：在可写层创建 whiteout，让下层文件在 merged 中不可见。
- 同名目录会合并，同名文件上层覆盖下层。

所以 Agent 运行时的修改，默认写进 **Writable Layer**。容器停止后可写层还在，删除容器才丢失；`docker commit` 可以把可写层固化成新镜像，但一般不推荐作为常规做法。

## 3. “独立更新”怎么做

Docker 不能像拼积木一样在运行中热替换 lowerdir。更准确地说：

- 改 Base：重建 base 镜像，再重建上层镜像，用新镜像启动新容器。
- 改 Toolkit：重建 toolkit 层及其上层，旧容器不受影响。
- 改 Workspace：  
  - 如果 `COPY` 进镜像，需要重建镜像。  
  - 如果挂载 volume/bind mount，直接改宿主机目录即可。
- Agent 运行时修改：写 Writable Layer 或 volume。  
  - 要持久化，用 volume。  
  - 要保留容器状态，用 `docker commit`，但可复现性差。

关键限制：**运行中的容器不能动态换层**。OverlayFS 的 lowerdir 在容器创建时基本固定，独立更新发生在构建和重建阶段。

---

## 4. 推荐实践

- 变化频率低的放底层：Base → Toolkit → Workspace → Writable。
- 工具链放镜像层，固定版本，便于复用和缓存。
- 任务数据、代码工作区用 volume/bind mount，不要固化进镜像。
- 合并 `RUN`，清理 apt 缓存，减少层数和体积。
- 用 `.dockerignore` 避免把无关文件打进 Workspace 层。
- 非 root 运行；必要时 `--read-only` + `tmpfs`/volume。
- 多阶段构建可把构建工具和运行时分离。
